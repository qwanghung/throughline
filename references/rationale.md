# Rationale: why this, why not the others

## Evidence ladder

From weakest to strongest. Use the strongest rung you have, and say which rung it is.

1. Designer's opinion or best practice
2. A single anecdote or support ticket
3. Direct user quote(s), with how many people
4. A pattern across research sessions (n = …)
5. Behavioural data: funnel, drop-off, time on task, error rate
6. A business metric tied to the problem: revenue, churn, support cost

Never claim a higher rung than you have. "3 of 8 participants" is stronger than "users struggle".

## Options and criteria (QOC)

"Optimal" means the best option against the stated criteria under the stated constraints. It doesn't mean perfect. Show it:

| Criterion (from the audience's "cares about") | Weight | Option A (chosen) | Option B | Option C / do nothing |
|---|---|---|---|---|
| … | high | ● | ◐ | ○ |

- Take the criteria from the audience card, not from design heuristics alone.
- Include "do nothing" or "the existing pattern" as an option when it's realistic.
- Say the criterion each rejected option lost on, in one line each.
- Name the trade-off you accepted with the chosen option.

## Problem × feature map

| | Feature 1 | Feature 2 | Feature 3 | Coverage |
|---|---|---|---|---|
| Problem 1 | ● | | ◐ | Solved |
| Problem 2 | | ● | | Solved |
| Problem 3 | | | ◐ | Partly: [what's left] |
| Problem 4 | | | | Not solved: [deliberate? next step] |

● directly solves · ◐ helps · blank = no effect

Checks:
- A feature column with no mark: cut the feature or move it to the appendix.
- A problem row with no mark: say so in the pitch. Don't hide it.
- If every cell is ●, the map is too generous. Re-check it.

## Decision record (for written docs and handover)

```
Decision:      …
Context:       the problem and its evidence, one paragraph
Options:       A (chosen), B, C — one line each with the deciding criterion
Consequences:  what gets better, what we accept, what we'll watch
Revisit if:    the signal that would change this decision
```
