# Formats

| Format | Budget | Shape |
|---|---|---|
| Elevator / hallway / quick answer | 30 s, ~75 words | Point → proof → push, one sentence each |
| Spoken pitch | 3 min, ~400 words | Hook → point → 2–3 problems → principle → demo of 2–3 features → map in one sentence → push |
| Long talk / review meeting | 10 min | As the spoken pitch, plus the options table and the strongest objection |
| Written doc | 1 page, plus appendix | SCQA opening paragraph, problems, principle, solution, map table, options table, ask. Details go in the appendix |
| Slides (spoken) | 1 point per slide | A single word, number or visual. The narration carries the argument. See "Slides" below |
| Slides (sent to read) | 1 idea per slide | Slide title = the claim, as a full sentence. Body = the evidence. No title-only slides like "Problems" |
| Figma annotation | ≤ 3 lines per decision | Decision → which problem it serves → the option it beat |
| Design-language doc (showcase) | Scannable; story up top, build detail folded | Imaginative hook → short origin story → the idea as image lines → each behaviour as Image → Rule → Build → where it could go |

## Spoken vs written

- **Spoken**: short sentences. One number per sentence. Signposts are allowed ("two problems; first…"). Repeat the ask at the end. That's the one place repetition earns its keep.
- **Written**: tables carry the map and the options. Readers skim, so headings state claims, not topics.
- **Both**: the first sentence's only job is to make them want the second. Open with the hook (`spine.md`) or a concrete observation, never with an agenda or a definition.

## Slides for a spoken pitch

- No title-plus-bullets layout. Extra slides cost nothing, so split every point onto its own slide.
- Keep each slide to one word, one number or one visual. Leave a slide blank when you want the audience looking at you.
- Use transitions with meaning:
  - Smart animate or a dissolve when one point spans several slides, so it reads as continuous.
  - A hard cut for a new point.
  - A switch from light to dark for a major section change.
- Animate UI only to highlight what the narration is talking about at that moment.
- Keep designs and slides in one place (for example, Figma Slides) so frames stay current.
